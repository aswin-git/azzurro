Collection & Insights Methodology

1. Review Collection & Deduplication

Booking.com does not offer a public reviews API. The companion Python scraper fetches Booking.com's public reviewlist.html endpoint sorted newest-first, applies multi-selector HTML parsing with exponential backoff and polite rate limiting, and deduplicates every review using a deterministic SHA-256 hash stored in SQLite.

2. Operational Topic Classification (8 Categories)

Each review is analyzed separately across its Liked and Disliked sections using a transparent domain lexicon covering Cleanliness, Check-in experience, Staff/receptionist behaviour, Noise, Facilities, Location, Room condition, and Value for money. Ratings are bucketed into Positive (7.0+), Neutral (5.0–6.9), and Negative (<5.0).

3. Current Week vs. Previous Week Logic

When live scraping runs daily, the Current Week KPI compares the last 7 calendar days against the preceding 7 days. On a static snapshot, it automatically anchors to the latest active 7-day window containing reviews and labels the exact dates so operations staff always see accurate comparisons.

4. Limitations & Sample Data Note

This dashboard is pre-loaded with 76 real guest reviews collected across the four Azzurro Hotels properties (combining Booking.com reviews and partner OTA listings where Booking.com's drawer is client-side gated), alongside each property's live Booking.com overall rating. Lexicon matching is fast and explainable, though sarcasm or unstated context can be improved by enabling the optional LLM classifier hook in the backend.
